# 大熊交易课程 — 量化转化项目

> 从零散的交易教学，到可回测、可执行的量化交易系统。

---

## 一、项目背景

### 1.1 源材料

Taiwan Bear Trading（大熊交易学院）的完整交易教学体系，包括：

- **课程视频** 7 章（风险管理+技术分析全体系）
- **实战分析视频** 12 个（BTC/ETH/XRP/LINK 等实盘分析）
- **PDF 周报** 15 份（2020-2021 年每周市场报告，覆盖 30+ 币种）
- **XLSX 实盘记录** 11 份（讲师真实交易持仓表，含入场/目标/止盈数据）
- **投资策略文档** 1 份（主流&山寨币投资方法论）
- **PPTX/DOCX 课程讲义** 第 7 章详细版

### 1.2 核心挑战

讲师的交易方法论基于 **肉眼的整体感知**——模糊、连续、容忍细微变形。将这种人类直觉转化为 Pine Script 可执行的条件，需要：

1. 把隐性的视觉判断显性化为数值条件
2. 解决单个参数脆弱的序列匹配问题
3. 建立与讲师直觉一致的统计共识机制

### 1.3 指导思想

- **四阶段工艺**：学 → 建 → 辩 → 铸
- **两条知识线**：市场机理（A 线）+ 执行方法（B 线），耦合验证
- **统一内核**：所有形态归约到 `供需区 + 动能转换 + 优势价格 + RR≥2:1`
- **多参数共识**：不找"正确的 zigzag 参数"，让 N 组参数投票

- 形态识别引擎（多参数共识 + 弹性几何搜索）

### 阶段四：量化转化

**数据基础**（阶段三产出）：

- Telegram 515 话题 + 微信 30 话题，全部完成概念标签+视觉识别标签

- 75 张 TV 快照 + 91 张 docx 内嵌图，覆盖 ~30 个品种

**从 166 张图表标注要素中提炼的量化优先级**：

| 要素 | 出现率 | 量化可行性 | 优先级 |
|------|--------|-----------|--------|
| Fib 0.618/0.786 回撤 | ~90% | 高 — Pine `line.new` + 高低点计算 | P0 |
| 水平支撑/阻力线 | ~85% | 高 — 摆动点极值 + 触碰次数 | P0 |
| 矩形框标记（入场/止损/目标） | ~70% | 中 — 需结合结构识别 | P1 |
| 结构转换（阻力↔支撑） | ~60% | 中 — 需识别突破+回踩 | P1 |
| 趋势线（斜线） | ~40% | 中 — 多点拟合 | P2 |
| 涨平涨/跌平跌/N字结构 | ~50% | 中 — 需拐点序列匹配 | P1 |
| 看涨吞没/影线形态 | ~30% | 高 — K线形态规则匹配 | P0 |
| RSI/MA 指标 | ~20% | 高 — Pine 内置函数 | P2 |
| 假突破识别 | ~20% | 中 — 突破后快速收回检测 | P2 |

**核心量化策略（修订版）**：

1. **分层递进，不追求一步到位**：
   - L0: K线本体 → 吞没/影线/十字星等形态（Pine 可直接计算）
   - L1: 摆动点 → Zigzag 多参数共识 → HH/HL/LH/LL 序列
   - L2: 结构 → N字型/涨平涨/跌平跌/结构转换（依赖 L1）
   - L3: Fib → 自动从 L1 摆动点画 0.618/0.786/1/-0.272（依赖 L1）
   - L4: 综合信号 → 结构+Fib共振 = 入场/止损/目标

2. **每个 L0-L3 层独立可测**，输出可视化标记（line/label/box），不耦合

3. **Pine Script 实现原则**：
   - 所有阈值参数定义为 `input()`，标注来源话题编号
   - 先做 L0（K线形态）和 L1（Zigzag共识）— 这是最成熟的
   - 每个指标独立文件，通过 Pine `indicator()` 叠加使用
   - 用 `line.new`/`box.new`/`label.new` 在图表上直接显示检测结果

4. **回测数据准备**（基于数据需求清单）：
   - 优先品种：BTCUSD、ETHUSD、XRPUSD（出现频次最高）
   - 优先周期：日线（50+张图）、4H（20+张图）
   - 时间范围：2020-2021 为主

## 五、阶段三实操经验教训（话题标注过程中积累）

### 5.1 图表获取

1. **TradingView 快照链接（`tradingview.com/x/...`）未过期**，但需通过已登录的 TradingView Desktop CDP 访问（直连超时）
2. **解决方案**：通过 CDP 控制已登录 TradingView Desktop → `Page.navigate(url)` → `Page.captureScreenshot()` → 本地保存 PNG（需跳过 Oops 页面）
3. **前提**：TradingView Desktop 必须以 `--remote-debugging-port=9222` 启动
4. **ChatExport 原始 HTML 中的图片附件在蒸馏 JSON 中可能丢失**，必须同时检查原始 HTML

### 5.2 视觉标签规范

1. **视觉标签只写图表上 VL 实际看到的标注元素**（线/箭头/方框/文字/形态/价位）。绝不从文字讨论推断
2. **概念标签从文字讨论中提取**，不做图表视觉推断
3. **区分相似视觉元素**：趋势线（单斜线）≠ 下降通道（双平行线），不可混用
4. **基础视觉元素不能遗漏**：支撑线、阻力线、趋势线、影线、K线形态，即使"太基础"也必须标注
5. **每张图表必须 VL 先看，再写标签**。先写标签再 VL 看的流程会导致大量错误
6. **VL 描述需要交叉核实**，不能照抄——模型可能把趋势线说成通道、把箱体说成矩形整理

### 5.3 话题标注流程（正确顺序）

```
1. 从蒸馏JSON读取话题文本 → 提取所有TradingView链接
2. 同时检查原始HTML和ChatExport照片目录是否有图片附件
3. CDP逐个截图 → 本地保存
4. VL逐帧分析 → 只描述实际标注元素
5. 从VL描述提取视觉标签 + 从文本提取概念标签
6. 和用户逐一讨论确认
```

### 5.4 标签三列结构（话题1复盘后确立）

标签必须三列，缺一不可：

| 列 | 含义 | 来源 | 示例 |
|----|------|------|------|
| **图表内容** | VL 实际看到的标注元素（线/箭头/文字/方框/价位） | VL 分析报告 | "3处文字标注+箭头，无水平线" |
| **概念标签** | 图表+文字讨论共同传达的交易概念 | 图表+文字讨论 | "影线判断买压/卖压区间=识别结构" |
| **视觉识别标签** | 自动识别此模式需要检测的视觉特征（L0-L8映射） | 从图表内容提炼 | "L0:识别长影线 / L3:影线形成的结构区间" |

⚠️ 视觉识别标签不是"图表上画了什么"，而是**"如果要自动识别这个模式，系统需要检测什么特征"**。它是量化转化的桥梁。

### 5.5 修正时不要删正确内容

修正标签错误时，缺什么补什么——不要把已有的正确标签一起删掉。

### 5.6 每个话题讨论完立即更新标签文档

每完成一个话题的复盘，立刻写入 `话题标注记录.md`。不要攒多个话题一起写。

### 5.7 一张图表可以服务多个子话题（话题4复盘）

t4a 的灰色方框同时服务于 4a（Fib演示）和 4b（大阳线支撑正例）。不要假设一张图=一个概念。

### 5.8 正例和反例都要标注

很多话题同时给出正例和反例。标注时要明确区分，反例的视觉标签也要提取。

### 5.9 视觉识别标签格式

格式：**"识别XXX"**，直说识别什么。不要写识别方法、不要写对应量化层、不要写颜色/矩形/"灰色矩形覆盖的区间"。示例：

- ✅ `识别需求区` / `识别支撑区域` / `识别回调入场路径`
- ❌ `L3: 识别灰色矩形标注的横向价格带` / `L5: 识别入场位与阻力位距离比值`

### 5.10 CDP截图+VL对复杂图表页面准确度有限

`tw.tradingview.com/chart/` 类型的实时图表页面包含多张图+文字，CDP截图可能只捕获部分内容，VL描述不够准确。这类链接优先要求人工截图。

### 5.11 VL说的"级别"需要核实

VL可能把1W（周线）说成"月线"。每次VL报出时间级别时必须自己核查图表上的级别标记，不可照抄。

### 5.12 VL标注描述 vs 价格走势描述必须分开

VL经常混在一起——把K线价格走势（"双底""上涨趋势"）说成标注。每次VL输出后要追问：这到底是画上去的线/框/文字，还是你在描述走势？

### 5.13 每张图表记录数据要素

每张图表标注完成后，必须提取：品种、时间周期、图表时间范围、关键价位。写入数据需求清单，方便后期获取历史数据回测。

### 5.14 写入标签文档前必须完成图片识别

有图表的必须 CDP 抓图 → VL 看标注 → 写入标签。不可跳过图表识别直接写入文档。

### 5.15 新发现的概念（话题12-19中补充课程未覆盖的）

- **分批止盈陷阱**：除非第二目标RR特别理想，分两个目标位会拉低平均RR
- **干净突破**：吸筹/派发区突破应该是"干净"的果断突破，有幅度才能止损韭菜
- **Pin Bar陷阱**：可能是主力平仓获利了结，不是主力入场。不能单独做交易
- **决定性突破** = 前面是形态/下跌趋势后的强势上涨 + 影线回踩确认
- **拉尾盘**：趋势末端常有快速大涨，出现在几轮上涨后，标志行情接近尾声
- **Fib起点选择深度**：选最左边因为0.618处才有结构位。突破趋势线前涨幅小=同一段趋势。激进取高点入场=盈亏比较差

### 5.16 常见错误

| 错误类型 | 示例 | 纠正 |
|---------|------|------|
| 从文字推断视觉 | 讨论Fibonacci → 标签写"识别Fib0.618" | 图表上没画Fib就不能写 |
| 术语不精确 | VL说"通道" → 照抄 | 核实是单线还是双线 |
| 遗漏基础元素 | 只写了"识别双底" | 支撑线/颈线也必须标注 |
| 跳过图表直接标注 | 以为文本描述够用 | 文本只描述逻辑，图表才描述视觉 |
| 蒸馏数据当完整 | 只查JSON的attachments | 必须同时查原始HTML和照片目录 |

## HA Zigzag 指标开发记录（2026/08/06-07）

### 目标

构建一个基于 Heikin Ashi 的折线指标，用于识别趋势段和震荡区，作为 L1 层的摆动点检测方案。

### 版本迭代

| 版本 | 文件 | 核心思路 | 结果 |
|------|------|---------|------|
| v1 | `HA_Zigzag_v1_baseline.pine` | HA 单平滑 → 拐点 → 折线 | 碎段多，但拐点位置正确 |
| v2 | `HA_Zigzag_v2_oscillation.pine` | v1 + 震荡区比值识别 + 蓝/黑颜色区分 | 碎段多，震荡检测被 v5 继承 |
| v3 | `HA_Zigzag_v3_double_smooth.pine` | 对拐点序列做 HA_Open 二次过滤 | ❌ 过滤掉了真正的极值点，本质缺陷 |
| v4 | `HA_Zigzag_v4_momentum.pine` | 动量曲线 SMA(close-open) 替代 HA 方向判断 | ❌ 效果不如 v2 |
| **v5** | `HA_Zigzag_v5_chanlun.pine` | HA实体包含处理 + 缠论分型 → 笔 + HA实体/实际价格双轨震荡检测 | **✅ 当前最佳** |

### v3 失败原因分析

v3 对拐点序列用 HA_Open 线进行二次过滤——在 HA_Open 线附近的拐点被视为"噪音"丢弃。但这忽略了：真正的极值可以在任何位置，和平滑线的距离无关。过滤导致了两个问题：
1. 真正的极值拐点被错误丢弃
2. 丢失后试图用合并弥补，但合并的 `max/min` 无法恢复已丢弃的极值

**教训**：过滤应该发生在**方向信号层面**（决定何时切段），而不是**拐点价格层面**（决定拐点价格是多少）。

### v4 失败原因分析

动量曲线 SMA(close-open) 在理论上合理——平滑买卖力度比平滑价格更直接。但实际效果不如 HA：
- SMA 的滞后比 HA 更严重（动量曲线穿越零轴需要更多确认）
- 动量曲线忽略了价格的绝对位置——只看 K 线实体，不看影线
- HA 的 OHLC 四值平均天然包含了影线信息和价格位置

### v5 成功分析（2026/08/08）

**核心突破**：用缠论的包含处理 + 分型确认替代了 v1-v4 的"HA 变色即切段"范式。

| 层 | 技术 | 解决的问题 |
|----|------|-----------|
| 包含处理 | HA 实体被前一根完全包含 → 丢弃该 bar | 消除单根 flicker 噪音 |
| 分型识别 | 处理后序列三根确认顶/底分型 | 只有走出独立方向才产生拐点 |
| 交替合并 | 两同向分型 → 保留更极端的价格 | 保证 H-L-H-L 交替 |
| 双轨震荡 | HA 实体比值 + 实际价格比值，任一命中即震荡 | 震荡检测更全面 |

**v5 对比 v2 的本质区别**：
- v2：HA 单根变色 → 立刻切段 → 碎段多，事后用震荡标记区分
- v5：HA 实体包含处理 → 三根分型确认 → 碎段在源头被过滤

**震荡检测设计**：
- 分型识别用 HA 实体范围（缠论标准），笔端点坐标用实际 K 线 high/low（视觉准确性）
- 震荡比值同时用 HA 实体价格和实际 K 线价格，任一低于阈值即标记
- 蓝 = 震荡，黑 = 趋势

### 当前状态与下一步

- **v5 作为当前最佳保留**，包含处理 + 分型确认从根本上解决了碎段问题
- 震荡检测双轨制运作良好
- 可选优化方向：分型最小间距约束 / 笔的力度过滤（ATR 比值）

## HA Zigzag v7 开发记录（2026/08/08）

### 缘起

dman103 的 Heikin Ashi Trend Indicator (HAT) 在 TradingView 上有 2300+ 赞。核心思路：Heikin Ashi + Tilson T3 平滑 → 逐 bar 连续信号。想借鉴它的 T3 平滑来做 zigzag 拐点标记。

### HAT 原理解析

```
原始OHLC → HA 转换 → T3 平滑(四通道: o2/c2/h2/l2)
→ o2 < c2 看涨(画在 T3(haLow)), o2 > c2 看跌(画在 T3(haHigh))
→ 挤压预警: T3(haClose)和T3(haOpen)的百分比差 < 阈值 → 反转前兆
```

T3 公式（原版用递归 GD）：
```
gd(src, len, a) = EMA(src,len)*(1+a) - EMA(EMA(src,len),len)*a
t3 = gd(gd(gd(src)))  → 等价 6层级联 EMA
```

v7 简化：factor=0 → T3 退化为三重 EMA。不需要 T3Factor 参数。

### v7 开发历程

**第一版**（基线）：单变量 extreme 追踪，方向切换时推拐点。问题：拐点标在方向切换 bar 上，不在实际极值 bar。

**追踪优化**：尝试双变量追踪（highExt/lowExt）、段内联动重置、回望修正、双向确认……多轮迭代都不对。根本原因是拐点追踪从**方向切换 bar** 开始，而非从**上一拐点 bar** 开始。

**最终方案**（bar_index 回查）：彻底放弃追踪变量。方向切换时，从上一拐点的 bar_index 往回扫描，用 findHighest/findLowest 逐 bar 找极值。

```
toDown(涨→跌): 从上一 LOW 的 bar_index 到当前 → 逐 bar 扫最高 high → HIGH
toUp  (跌→涨): 从上一 HIGH 的 bar_index 到当前 → 逐 bar 扫最低 low  → LOW
```

**MTF 确认版**（当前 `pine/HA_Zigzag_v7_hat.pine`）：三套 T3(20/15/10) 同时运行，20 做主框架——

| 条件 | 结果 |
|------|------|
| 15/10 端点存在 + 类型一致 + 中间拐点完全一致 | 用 15/10 替换 |
| 否则 | 保留 20 |

**已修复的 bug**：
- Pine Script `and`/`or` 不短路求值 → 拆为嵌套 if
- 同向合并分号语法错误 → 每行独立 + doMerge 函数
- 端点类型未检查导致 H/L 同 bar → 加 typesMatch 检查
- 扫描范围包含枢轴 bar 自身 → `back - 1` 排除起点

### 下一步：震荡识别

v7 已产出交替的 H/L 拐点序列。下一步用这些拐点识别震荡。

**震荡的本质**：价格重叠。同向线段（上涨段对上涨段、下跌段对下跌段）的价格区间有交集 → 形成中枢。多段重叠延伸 → 震荡区扩展。新走势脱离重叠区 → 突破。

这统一了所有震荡形态：箱体（高低持平）、三角（收敛）、旗型楔型（倾斜但重叠）、扩张（扩大但重叠）、无规则（任意重叠）。

与 v5 缠论的方法对比：v5 用分型 + ER 比值 + 摆动点边界做震荡检测。v7 可以基于"同向段重叠"做更纯粹的缠论中枢定义。
